# 项目需求

- 项目名称：Tibo Radar
- 当前版本：v0.2 开发中
- 最后更新：2026-09-10

## 这个项目要解决什么问题

Codex 偶尔会进行全局福利重置，或向用户发放可储存的重置卡，但没有固定
日程。用户希望根据 Tibo 的公开社交动态、官方状态事件和历史节奏，提前
知道未来一两天发生福利重置的可能性，而不是等到账后才发现。

## 谁会使用

主要给经常使用 Codex、需要安排高用量任务的 macOS 用户使用。第一版先为
单个本机用户服务。

## 第一版必须做什么

- [x] 获取公开 forecast、timeline、Tibo feed 和 OpenAI Status 数据。
- [x] 分别估算全局重置、普发重置卡与综合概率。
- [x] 给出 24 小时和 48 小时预测，并解释主要加减分原因。
- [x] 提供命令行快照和本地网页。
- [x] 当概率首次跨过阈值或出现已确认事件时发送 macOS 通知。
- [x] 保存最近快照和通知状态，避免重复提醒。
- [x] 网络失败时使用最近缓存并明确标记数据陈旧。
- [x] 用离线数据覆盖核心预测、缓存回退与去重逻辑。

## 第一版暂时不做什么

- 不自动兑换、购买或使用重置卡。
- 不保存 Codex、ChatGPT 或 X 登录凭据。
- 不直接接入付费 X API；先使用公开聚合数据并保留替换接口。
- 不发布到公网，不创建云端账户系统。
- 不制作签名安装包和自动更新。
- 原生菜单栏壳放到第二阶段；第一版先验证预测质量和提醒节奏。

## 第二阶段：原生菜单栏 App

- [ ] 交付独立的 `Tibo Radar.app`，无需浏览器、终端或 Python。
- [ ] 只常驻 macOS 菜单栏，点击图标显示紧凑预测面板。
- [ ] App 运行时每 15 分钟刷新，并保留手动刷新。
- [ ] 使用 macOS 原生通知，并避免相同信号重复提醒。
- [ ] 支持 macOS 13 及以上版本；当前验收包面向 Apple Silicon。

## 用户怎样使用

1. 启动本地雷达，查看当前 24 / 48 小时概率和证据。
2. 让后台观察器按固定间隔刷新。
3. 收到高概率或明确重置通知后，再决定是否加速使用剩余额度。

## 怎样判断第一版完成

- [x] 新机器按 README 可以启动。
- [x] 断网时不会崩溃，并显示缓存时间。
- [x] 全局重置和重置卡不会混为同一事件。
- [x] 相同事件不会重复通知。
- [x] 所有测试通过，网页在本机浏览器检查无明显布局问题。

## 现在还不确定什么

- [ ] 免费公开数据源的长期稳定性和更新延迟。
- [ ] 后续是否购买 X API，以获得最早的主帖和回复信号。
- [ ] 是否申请 Developer ID 并制作面向其他设备的正式签名安装包。

## 风险和外部依赖

- Tibo 的回复可能比主帖更早出现信号，但第三方聚合可能遗漏回复。
- 历史样本只有几十次，概率只能作为决策辅助，不能当作承诺。
- 新模型发布期会造成事件聚集，必须避免用短期平均值过拟合。
