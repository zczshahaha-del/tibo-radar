# 主要依据优先展示最新公开信息

## 这次修改做了什么

- 把 Tibo feed 的抓取时间、最新帖子时间和最新信号时间交给 AI。
- 把上游 `radar_context` 中最新的普通动态交给 AI，用于判断“近期仍活跃但没有
  新的重置预告”，同时明确禁止把普通动态当作正面信号。
- 根据证据来源 URL 或来源 ID 找回原始发布时间，在本地代码中按新到旧排序，
  不再依赖模型返回顺序。
- 在每条可识别时间的依据标题旁显示日期；超过 72 小时的内容标为“历史”。
- 保持旧版 AI 快照兼容；缺少来源日期的依据仍可正常显示，并排在有日期依据后。
- 修复候选 App 暴露的菜单栏窗口裁切：改用标准 `NSStatusItem` 和 `NSPopover`
  承载现有 SwiftUI 页面，展开时明确修改 `contentSize`，保留向下展开交互。
- 关闭内容重排和弹窗尺寸的叠加动画，展开时固定上方预测卡片，只在底部显示依据。
- 恢复菜单栏原有的外部点击关闭行为；点击桌面、其他应用或菜单栏空白处会收起弹窗。
- 为 Tibo 回复补全父帖和引用帖正文；AI 必须结合完整会话判断，补全失败时不得
  猜测代词、日期或把上下文不明的回复当成明确正面信号。
- 父帖提出 banked reset 且 Tibo 同意时，只提高重置卡和综合概率；产品发布语境
  中的 Tuesday 不作为重置时间。
- 移除占位用的 SwiftUI `Settings` 场景，避免点击菜单栏时恢复空白的
  “Tibo Radar Settings”窗口；AI 设置仍保留在弹窗内。
- 让 `NSPopover.contentSize` 成为唯一的弹窗尺寸来源，关闭 Hosting Controller
  自动尺寸约束；展开时先扩容再插入依据，避免偶发向上偏移。
- 在收起状态提前测量三条依据的真实布局高度，展开时使用测量值；640 仅作为测量
  完成前的安全回退值，长文案不裁切、短文案不留下大块空白。
