# 制作原生 macOS 菜单栏 App

## 为什么要做

现有版本只是本地网页和启动脚本，不符合用户对“App”的预期。用户已经确认
菜单栏概念图，下一步要把已验证的预测能力做成真正可双击运行的 macOS App。

## 这次要做什么

- 使用原生菜单栏图标和弹出面板呈现预测结果。
- 在 App 内采集公开数据、缓存并计算三类概率，不依赖 Python 或终端。
- App 运行时每 15 分钟后台刷新；跨阈值或出现新事件时发送系统通知。
- 交付可以直接双击运行的 `Tibo Radar.app`。
- 为预测核心、缓存和构建流程补测试与文档。

## 这次不做什么

- 不加入开机自启动、自动更新和 App Store 发布。
- 不购买 X API，不登录 ChatGPT、Codex 或 X。
- 不自动兑换或使用重置卡。
- 不在这一分支合并到 `main`；完成后先交给用户验收。

## 怎样判断完成

- [x] Finder/LaunchServices 可以启动 `.app`，启动时不需要终端窗口。
- [x] App 只常驻菜单栏，不显示 Dock 图标。
- [ ] 点击菜单栏图标可看到综合、全局、普发卡和定向补发概率。
- [x] 手动刷新和每 15 分钟自动刷新都能工作。
- [x] 网络失败时继续显示缓存，并明确标记数据陈旧。
- [x] 通知只在概率跨过阈值或出现新明确事件时发送一次。
- [x] Swift 自动测试和 Release 构建通过。
- [ ] 实际启动 App，检查菜单栏图标、面板布局和退出流程。
- [x] 交付包中不包含密钥、缓存、个人数据或开发日志。

## 风险和不确定问题

- 数据或存档：有，只在 `Application Support/TiboRadar` 保存公开缓存和去重状态。
- 登录、权限或安全：有，系统通知需要用户在 macOS 中授权；不申请其他权限。
- 接口：有，第三方公开 API 结构变化时需要保持缓存回退和错误提示。
- 配置和发布：有，首个原生包采用本机临时签名，只面向当前 Apple Silicon Mac 验收。
- 外部服务：有，依赖 `codex-reset.com` 与 OpenAI Status 的公开接口。
