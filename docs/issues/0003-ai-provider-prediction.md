# 用 DeepSeek / 千问替换规则预测核心

## 为什么要做

原生菜单栏候选版能够联网抓取公开信息，但概率仍由本地关键词和加减分规则
产生。用户已明确否决这种核心预测方式，并确认改为用户自己填写 API Key，
由 DeepSeek 或千问理解原文、综合证据并给出概率。

## 这次要做什么

- 在 App 内提供 DeepSeek / 千问供应商切换。
- 用户自行填写 API Key；密钥只保存在 macOS 钥匙串。
- 允许修改模型名称，使用安全的官方默认接口地址。
- 刷新时先获取现有公开数据，再交给所选 AI 做语义判断。
- 千问请求开启官方联网搜索；DeepSeek 分析 App 已采集的公开原文。
- AI 输出固定结构的全局重置、普发重置卡、故障补发、24 / 48 小时概率、
  置信度、时间窗口、支持证据和反面证据。
- AI 不可用时显示明确错误，可以继续展示上次成功的 AI 结果；不得回退到
  规则概率并伪装成 AI 判断。
- 增加设置、连接测试、解析、缓存和密钥安全测试，并更新交付文档。

## 这次不做什么

- 不提交、同步或记录任何真实 API Key。
- 不支持任意自定义服务地址，避免把密钥误发给非官方主机。
- 不购买 X API，也不登录用户的 X 账号。
- 不自动兑换、购买或使用重置卡。
- 不在用户验收前合并到 `main`。

## 怎样判断完成

- [x] 首次启动没有 Key 时，引导用户进入设置而不是显示规则概率。
- [ ] DeepSeek 和千问都可以保存各自的 Key、切换供应商和测试连接。
- [x] Key 存入 macOS 钥匙串，UserDefaults、缓存、日志和交付包均无明文密钥。
- [x] 刷新请求使用所选供应商和模型，并解析为同一套严格数据结构。
- [x] 千问开启联网搜索；DeepSeek 的能力差异在界面中明确说明。
- [x] AI 返回无效数据、鉴权失败、限流或断网时给出可理解的错误。
- [x] AI 失败时保留上次成功快照，但明确标为旧结果。
- [x] 不再调用规则 `Predictor` 生成正式概率。
- [x] 自动测试、Release 构建、签名检查和 2x 视觉快照通过。
- [ ] 用户使用真实 Key 检查实际设置界面和 AI 预测结果。
- [ ] 用户检查真实 App 后明确接受，才允许合并。

## 风险和不确定问题

- 数据或存档：有，AI 快照会缓存在本机；只包含公开证据和模型判断。
- 登录、权限或安全：高，API Key 必须使用 macOS 钥匙串，错误内容必须脱敏。
- 接口：高，两家模型名称和响应格式可能变化，需要可编辑模型与兼容解析。
- 费用：有，每次刷新可能产生模型和联网搜索费用；没有 Key 时不发送请求。
- 外部服务：有，依赖 DeepSeek、阿里云百炼和公开数据源的可用性。
- 发布：当前仍为本机临时签名，仅用于当前 Apple Silicon Mac 验收。
