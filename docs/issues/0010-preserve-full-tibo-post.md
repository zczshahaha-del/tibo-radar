# AI 必须看到完整的 Tibo 原帖

## 问题现象

2026-09-12，Tibo 原帖末尾明确写着 “a reset is also landing by midnight
today”，但 App 给出的未来 24 小时综合概率只有 25%，并解释成“没有明确未来
时间窗”“该次或已落地”。

## 怎样让问题再次出现

1. 数据源的 `feed.events[0].summary` 只保留原帖开头约 200 个字符。
2. 同一响应的 `feed.tweets[0].text` 保存完整原文，明确承诺当天午夜前重置。
3. `AIInputBuilder` 只把 `feed.events` 放入 AI 上下文，没有传 `feed.tweets`。
4. AI 因而看不到帖子末尾的承诺，按历史基准和最近重置间隔输出低概率。

## 真正原因

- 预测输入使用面向列表展示的截断摘要，而不是数据源已经提供的完整帖子。
- 提示词没有说明完整原文和摘要冲突时应以完整原文为准。
- 结构校验只能检查概率范围是否合法，无法发现“证据明确承诺但概率仍很低”这种
  语义矛盾。

## 修改范围

- 把近期 Tibo 帖子的完整 `tweets` 数据作为独立字段加入 AI 上下文。
- 限制传入数量和字段，避免无关元数据增加模型费用。
- 明确要求 AI 优先阅读完整原文，并正确处理帖子末尾的未来承诺和相对时间。
- 使用本次真实截断形式补回归测试。
- 不增加固定概率权重，不自动兑换重置卡，不改变两小时自动巡检频率。

## 怎样确认已经解决

- [x] 截断摘要与完整原文同时存在时，AI 上下文包含完整末尾承诺。
- [x] 提示词明确规定 `recent_tibo_posts.text` 优先于摘要。
- [x] DeepSeek 与千问仍使用相同的结构化概率输出和校验规则。
- [x] Swift 自动测试、Release 构建和候选 App 启动通过。
- [x] 用户在真实菜单栏 App 中检查新的预测结果，并于 2026-09-13 允许合并。
